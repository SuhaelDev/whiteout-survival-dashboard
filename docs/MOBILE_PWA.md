# iOS phone shell + PWA

How the dashboard behaves on an iPhone, and the rules to keep in mind when
changing it. Desktop rendering is deliberately untouched by everything here.

## The one switch everything hangs off

`<html data-shell="mobile|desktop">`.

It is set twice with the *same* predicate, and the two copies must stay in
step:

- an inline script at the top of `index.html`, so the first paint is already
  correct and a phone never flashes the desktop layout;
- `detectShell()` in `src/mobile.js`, re-evaluated on resize and rotate.

The predicate: a coarse pointer without hover **and** a short edge of 500px or
less. That is a phone in either orientation. iPads and desktops fail it, and so
does a desktop browser resized to a narrow window, because it still reports a
fine pointer. `?shell=mobile` / `?shell=desktop` forces either side for
testing.

`src/mobile.css` scopes every rule to `html[data-shell="mobile"]`, so no rule
in it can reach a desktop. That is the whole safety story.

## Files

| File | What it is |
| --- | --- |
| `src/mobile.css` | The phone layer. Loads after `styles.css`, so equal-specificity rules win. |
| `src/mobile.js` | Phone chrome (top bar, tab bar, sheet), input hygiene, SW registration. |
| `sw.js` | Service worker: app shell + game data offline. |
| `manifest.webmanifest` | Install metadata, icons, shortcuts. |
| `assets/icons/`, `assets/splash/` | Generated by `scripts/build-pwa-assets.py`. |
| `vercel.json` | Cache headers. `sw.js` and `index.html` must never be cached hard. |

## How the phone chrome talks to app.js

`mobile.js` never imports from `app.js` and `app.js` never calls into it. They
communicate through the DOM only:

- **Reads** `document.body.dataset.activeTab`, which `renderActive()` sets on
  every render (`app.js` ~8947). That doubles as the "the app just
  re-rendered" signal, via a `MutationObserver` on body attributes.
- **Reads** `#saveStatus` text for the header subtitle.
- **Switches module** by calling `.click()` on the real `#moduleNav
  [data-tab="…"]` button. `activeTab` and `renderActive()` are module-private
  in `app.js`, so this is the only way to change module without duplicating
  that logic — and it inherits `app.js`'s own scroll reset for free.
- **Moves** the `<aside class="sidebar">` node into the sheet. It is *moved*,
  not cloned, so every listener `bindEvents()` attached and every `innerHTML`
  target (`#moduleNav`, `#accountPanel`, `#saveStatus`) keeps working.

Consequences worth remembering:

- Anything injected inside a `.tab-panel` is destroyed on the next render. The
  tab bar and sheet are children of `<body>`; the top bar is the first child of
  `.main`, outside `.content-area`.
- The sheet is inert while closed, so `switchTo()` lifts `inert` across the
  synthetic click and restores it.
- CSS hiding the in-shell sidebar is gated on `data-mchrome="ready"`, which
  `mobile.js` sets only *after* the move succeeds. If `mobile.js` fails to
  load, the sidebar stays visible at the top of the page — degraded, but the
  app is still navigable.

## Layout decisions that are not arbitrary

- **The top bar is not `position: fixed`.** `focusActiveNutshell()` in
  `app.js` scrolls a target to viewport top with an 8px allowance; a fixed
  header would hide the thing it just scrolled to.
- **The sheet has no `visibility` toggle.** Flipping visibility in the same
  frame as the transform made WebKit start the slide from an indeterminate
  point and occasionally park the sheet half open. It stays in the layout,
  translated off-screen, with `pointer-events: none` and `inert`.
- **The chief profile collapses.** Those six fields sit inside the hero band
  and were taking about half of the first screen above every module's content.
- **Form controls are 16px.** Not a design choice: Safari zooms the viewport
  whenever a focused control is under 16px and never zooms back out cleanly.
  `styles.css` sets 11–13.5px on eleven control rules, one with `!important`,
  hence the blanket override.
- **Checkboxes are drawn as background images** on a transparent 44px control.
  Padding is ignored on a control with its default appearance, so that is the
  only way to get a real 44px target with a normal-sized visible box.
- **`backdrop-filter` is off on panels.** `styles.css` puts
  `blur(12px) !important` on `.panel`, `.metric`, `.game-style-panel`,
  `.chief-troop-card`, `.upgrade-nutshell` and `.inventory-check` — dozens of
  blurred layers compositing every scroll frame. The panels are already ~85%
  opaque, so a solid fill is visually near-identical and much cheaper.
- **The three.js canvas gets `touch-action: pan-y !important`.** `app.js` sets
  `touchAction = "none"` inline so a drag rotates the model, which turns the
  Chief Gear and Charms canvases into scroll dead zones on a phone. A CSS
  `!important` beats the inline style; vertical drags scroll, horizontal drags
  still rotate, and `app.js`'s existing `pointercancel` handler cleans up.
- **Horizontal overflow was almost always one cause:** a grid track whose
  implicit minimum is `auto`, so a single nowrap child sets the width of
  everything above it. `minmax(0, …)` and `min-width: 0` break the chain.

## Service worker

Cache names embed **two** version strings and both matter:

- `BUILD` — the `?v=` on `styles.css` / `mobile.css` / `app.js` in
  `index.html`.
- `DATA` — `ASSET_CACHE_VERSION` in `src/app.js` (~line 1370), which `app.js`
  appends to every `data/*.json` and `assets/game/*` request.

Bump `BUILD` in both `index.html` and `sw.js` when you touch the shell. Bump
`DATA` in both `app.js` and `sw.js` when you touch data. A change to either
drops the stale caches on activate.

Strategies:

| Request | Strategy |
| --- | --- |
| navigation | network-first, cached `index.html` on failure |
| `data/*.json`, `assets/game/manifest.json` | stale-while-revalidate |
| images | cache-first, capped at 400 entries |
| `.css` / `.js` / manifest | stale-while-revalidate |
| `/api/*` | **never cached** — `/api/state` carries a bearer token |
| `esm.sh`, `cdn.jsdelivr` | not intercepted; `app.js` already fails soft |

Two subtleties that are easy to undo by accident:

- Cache lookups are **exact-match first**. Matching with `ignoreSearch` up
  front would pair last deploy's `app.js?v=OLD` with this deploy's
  `index.html`. A loose match is only used as an offline last resort.
- `controllerchange` only triggers a reload when a controller was *already*
  driving the page. `clients.claim()` fires it on first install too, and
  reloading there means every first visit silently reloads itself.

`data/game-data.json` is 2.7 MB and is precached, so the first load costs about
3 MB and everything after that opens instantly and works offline. Item art
(~20 MB in `assets/game/`) is cached as you browse instead.

## Verification

Everything runs against a local server: `node scripts/dev-server.mjs 5173`.

| Script | What it proves |
| --- | --- |
| `scripts/ios-audit.mjs` | Every module in WebKit at iPhone size: no sub-16px controls, no sub-44px targets, no horizontal overflow, no console errors. Screenshots to `.ios-audit/`. |
| `scripts/pwa-check.mjs` | Manifest validity, every icon and splash image resolves, SW registers and precaches, hard offline reload still renders, deep links, and the desktop shell is untouched. |
| `scripts/desktop-parity.mjs` | Screenshots every module at 1440×900 against a checkout of the previous build and diffs pixel for pixel. |
| `scripts/sheet-cycle.mjs` | The sheet always lands fully open or fully closed, and the tab bar still navigates while the sheet is inert. |
| `scripts/diff-image.mjs` | Red-highlight overlay of where two parity screenshots differ. |

For `desktop-parity.mjs`, serve the baseline alongside:

```
git archive HEAD | tar -x -C /tmp/orig-site
cp scripts/dev-server.mjs /tmp/orig-site/scripts/
node /tmp/orig-site/scripts/dev-server.mjs 5174 &
node scripts/desktop-parity.mjs
```

It blocks service workers on purpose. The new build ships one, and letting it
serve the 2.2 MB hero from cache shifts decode timing, which shifts text
antialiasing over the band — noise that has nothing to do with CSS. Note also
that `chief-gear`, `charms`, `pets`, `experts` and `buildings` are *inherently*
non-deterministic (three.js canvases, `float` animations, lazily decoded
portrait art): they differ when the original build is compared to **itself**,
so judge them against a control run rather than against zero.

## Regenerating icons and splash screens

```
python3 scripts/build-pwa-assets.py
```

Writes `assets/icons/`, `assets/splash/`, and `scripts/splash-links.html` —
paste that last file's contents into `index.html` if the device list changes.
Safari matches a startup image by exact media query and shows a blank screen
when nothing matches, which is why every supported device gets both
orientations.
